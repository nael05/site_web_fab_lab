LÉGENDE
  PK        clé primaire (identifie chaque ligne)
  FK -> t   clé étrangère vers la table t
  UNIQUE    deux lignes ne peuvent pas avoir la même valeur
  IDENTITY  INTEGER GENERATED ALWAYS AS IDENTITY : numéro auto-incrémenté
  CHECK ck  contrainte de vérification, détaillée sous chaque table
  NULL      colonne facultative          NOT NULL : colonne obligatoire

CONVENTIONS
  - Noms en minuscules, snake_case, au singulier.
  - Argent en centimes (INTEGER) : 2500 = 25,00 EUR. Jamais de FLOAT pour l'argent.
  - Quantités en NUMERIC(10,2), dans l'unité de base : grammes, millilitres ou unités.
  - Longueurs en millimètres. Durées en minutes.
  - Dates avec fuseau horaire : TIMESTAMPTZ. Une date seule (sans heure) : DATE.
  - Emails enregistrés en minuscules par le back avant insertion.

ORDRE DE CRÉATION : les tables sont listées dans l'ordre où il faut les créer
(une table doit exister avant qu'une autre puisse pointer vers elle).

==========================================================================================================
  RELATIONS (clés étrangères)
==========================================================================================================
  table.colonne                    ->  table référencée          si le parent est supprimé
  ----------------------------------------------------------------------------------------------------
  code_otp.id_utilisateur          ->  utilisateur              CASCADE  (codes supprimés)
  conversation.id_client           ->  utilisateur              CASCADE
  message.id_conversation          ->  conversation             CASCADE
  message.id_auteur                ->  utilisateur              RESTRICT (refusé)
  projet.id_auteur                 ->  utilisateur              RESTRICT
  projet.id_produit_choisi         ->  produit                  RESTRICT (désactiver le produit)
  fichier.id_projet                ->  projet                   CASCADE
  etape.id_projet                  ->  projet                   CASCADE
  etape.id_admin                   ->  utilisateur              SET NULL (l'historique reste)
  bilan.id_projet                  ->  projet                   RESTRICT
  consommation.id_bilan            ->  bilan                    CASCADE
  consommation.id_produit          ->  produit                  RESTRICT
  publication.id_projet            ->  projet                   CASCADE
  photo.id_publication             ->  publication              CASCADE
  avis.id_projet                   ->  projet                   CASCADE

==========================================================================================================
  INDEX À CRÉER
==========================================================================================================
  PostgreSQL crée un index automatiquement pour les PK et les UNIQUE, mais PAS pour les
  clés étrangères. Sans index, chaque jointure ou suppression parcourt toute la table.

  idx_code_otp_utilisateur     ON code_otp (id_utilisateur)
  idx_message_conversation     ON message (id_conversation, date_envoi)
  idx_message_auteur           ON message (id_auteur)
  idx_projet_auteur            ON projet (id_auteur)
  idx_projet_produit           ON projet (id_produit_choisi)
  idx_projet_statut            ON projet (statut)          -- filtres de l'onglet Suivi
  idx_fichier_projet           ON fichier (id_projet)
  idx_etape_projet             ON etape (id_projet, date_debut)
  idx_etape_admin              ON etape (id_admin)
  idx_consommation_produit     ON consommation (id_produit)
  idx_photo_publication        ON photo (id_publication, ordre)

==========================================================================================================
  RÈGLES MÉTIER GÉRÉES PAR LE BACK (pas exprimables en contrainte SQL simple)
==========================================================================================================
  - Pièce > 260 mm sur un côté : autorisée seulement avec plusieurs fichiers de type 'stl'.
  - projet.id_produit_choisi : produit actif, consommable, en stock, et de la bonne
    catégorie (filament pour une impression 3D, tee_shirt pour un flocage).
  - Un avis : seulement si projet.statut = 'termine', posté par l'auteur du projet.
  - etape.id_admin et la clôture : seulement un utilisateur avec role = 'admin'.
  - Clôture « Projet fini » = UNE transaction : INSERT bilan + consommation,
    UPDATE produit.quantite_stock, UPDATE projet.statut, INSERT etape.
    Si le stock devient négatif, ck_stock fait échouer toute la transaction.
  - Changement de statut : uniquement selon la machine à états définie dans le back.
