Démonstration : aide-mémoire (10 minutes)

Projet de synthèse - L'agence de Calypso. Avant de commencer : 4 onglets de terminal ouverts (gw, agence, srv, tunnel Netdata) et le schéma du dossier à l'écran.

1. Le schéma (1 min)

Siège : gw relie le LAN 10.10.10.0/24, la DMZ 10.10.20.0/24 et Internet (NAT VMware). L'agence (routeur agence, LAN 10.10.30.0/24) est reliée à gw par un tunnel WireGuard 10.10.99.0/24 sur UDP 51820. Rien n'est ajouté sur Internet à part ce port. Supervision : Netdata sur srv.

2. Le tunnel (2 min)

ssh gw "sudo wg show"
ssh agence "sudo wg show"

À montrer : « latest handshake » récent des deux côtés, allowed ips (gw : 10.10.99.10/32 + 10.10.30.0/24 pour l'agence, 10.10.99.2/32 pour nomade), service activé au démarrage.

3. Les flux de l'agence (3 min)

Dans l'onglet agence (ssh agence), source 10.10.30.1 :

ping -I 10.10.30.1 -c1 10.10.10.10
dig +short -b 10.10.30.1 @10.10.10.10 intranet.calypso.internal
curl -s -o /dev/null -w '%{http_code}\n' --interface 10.10.30.1 http://10.10.20.10
nc -zv -w3 -s 10.10.30.1 10.10.10.10 22        # REFUSÉ (timed out)

Puis la ligne du journal, dans l'onglet gw :

sudo journalctl -k --since "-2min" | grep gw-forward-drop | tail -1

Montrer F15 à F19 dans /etc/nftables.conf (sudo grep -n "\[F1[5-9]\]" /etc/nftables.conf) : règles numérotées, placées avant le log.

4. Netdata, alertes et panne (3 min)

ssh -L 19999:127.0.0.1:19999 srv        # laisser ouvert, puis http://127.0.0.1:19999

Dans le navigateur : « Skip and use the dashboard anonymously », onglet Alerts, puis Events : l'historique de ping_host_reachable (CRITICAL puis CLEAR) de la panne provoquée. Panne en direct, si le temps le permet (CRITICAL en ~40 s, CLEAR en ~15 s après rétablissement) :

ssh agence "sudo systemctl stop wg-quick@wg0"     # panne
ssh agence "sudo systemctl start wg-quick@wg0"    # rétablissement

6. Questions individuelles : réponses courtes

QuestionRéponse
Pourquoi deux réseaux dans les AllowedIPs du pair agence côté gw, un seul pour nomade ?L'agence est un routeur : il y a un réseau derrière elle (10.10.30.0/24) en plus de son adresse de tunnel. Nomade est un poste seul : 10.10.99.2/32.
Un paquet de l'agence vers web : quelles chaînes de gw ? NAT ?prerouting (rien, le DNAT ne vise que le WAN), forward (règle F18), postrouting (le masquerade ne s'applique qu'à la sortie WAN). Il n'est pas traduit : web voit 10.10.30.1.
Le tunnel tombe : que voit Netdata ? Première commande ?Alerte ping_host_reachable en CRITICAL (et le port 22 de l'agence en échec). Première commande : sudo wg show des deux côtés, puis journalctl -k | grep 51820 sur gw.
Pourquoi le tableau de bord n'écoute-t-il que sur 127.0.0.1 ?Il n'a pas d'authentification : on ne l'expose pas. On y accède par un tunnel SSH, donc authentifié et chiffré.
Comment l'agence résout-elle intranet.calypso.internal ? Et si srv est éteint ?Via le DNS de srv (10.10.10.10) par le tunnel (F16, ACL de bind9 incluant 10.10.30.0/24) : un CNAME vers web, 10.10.20.10. Si srv est éteint, plus de résolution ni de proxy : seules les adresses IP restent joignables.
Si on ajoutait un poste dans l'agence, que faudrait-il de plus sur agence ?Activer ip_forward, servir le DHCP (ou une adresse fixe) avec agence comme passerelle et srv comme DNS, et des règles de transfert sur agence. Côté gw, rien : 10.10.30.0/24 est déjà dans les AllowedIPs et dans la variable AGENCE.
